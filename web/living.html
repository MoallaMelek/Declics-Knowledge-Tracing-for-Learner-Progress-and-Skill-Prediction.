Lire un parcours d’apprentissage

Un parcours musical du jeu de test, rejoué séance après séance. DÉCLIC résume ce qui a été observé, puis montre ce que le réseau prévoit pour l’essai suivant et ce qui s’est réellement passé.

D’où viennent ces profils ?

Données synthétiques d’intégration : ces parcours sont générés pour vérifier la mécanique avec les vrais poids entraînés. Ils ne disent rien de l’apprentissage réel.

Le parcours ne peut pas s’afficher pour l’instant

Si vous lancez DÉCLIC vous-même : exécutez Launch.ps1, attendez le message « prêt », puis réessayez. La dernière vue valide reste à l’écran quand il y en a une ; aucune valeur n’est inventée en attendant.

Diagnostic technique

Vérifiez l’état avec Launch.ps1 et /api/readiness. Ne fermez pas un autre serveur pour libérer son port.

Carte des concepts

Cliquez un point pour lire son histoire. Au clavier, dans la carte : flèches pour passer d’un concept à l’autre, Entrée pour l’inspecter, Échap pour revenir, + / − / 0 pour le zoom. Ailleurs sur la page : ← / → changent de séance, Espace lance la lecture.

Lire la carte sous forme de tableau

Empreinte des séances

Chaque anneau est une séance, de la plus ancienne (au centre) à la plus récente. Chaque arc est un concept réellement évalué ce jour-là ; un vide veut dire « non mesuré », jamais « échec ».

Le calcul du réseau

Vue chercheur. Le trajet réel d’une prévision : le passé fourni au réseau, les tenseurs construits, la mémoire GRU enregistrée, la sortie servie, puis la comparaison avec le résultat, révélé à la demande par le serveur. Les poids ne changent pas pendant le rejeu ; seule l’entrée change avec la séance choisie.

    Moment observé

    Ce que montre cette page. Un rejeu rétrospectif de parcours du jeu de test, jamais utilisés pour ajuster le réseau. Les concepts de la source n’ont pas de correspondance pédagogique approuvée ; aucun transfert au piano ; incertitude individuelle non validée ; pistes de pratique sans effet pédagogique démontré.
