# Posthoc cross-skill item-logistic control (EXPLORATORY)

Status: `exploratory_posthoc`. Not part of the predeclared 102-run study in
`artifacts/v2/axis7-v2-20261013-controlled/`. No neural retraining, no test-set
model selection; run once, read-only against the main study's own fixed splits
and saved validation-selected winners. Generated by `work/science_v2_global_control.py`.

Motivation: `EnhancedGRU` accumulates causal success/failure counts across **all**
knowledge components; the main study's `item_pfa` baseline only sees counts for the
**target** KC being queried. This control removes that specific confound by giving a
plain L2 logistic regression (`C=1`, `max_iter=2000`, no tuning) cross-KC counts,
known atomic item one-hot, train-only item difficulty, sequence position, and
smoothed global/target success fractions — fit only on each split's training
learners — then compares it, with the same 300-replicate grouped bootstrap
methodology as the main study, against whichever neural model the main study
already validation-selected for that split.

**Finding:** on forget-se, every paired 95% interval includes zero — EGRU's
log-loss advantage over the main study's weaker (target-KC-only) `item_pfa`
baseline does not fully survive once the control is given matched cross-KC
visibility. This does not show EGRU is worse; it shows that part of its measured
gain is explained by feature visibility, not recurrence alone. On music-mock,
`enhanced_gru` is never the validation-selected neural model (dkt/item_attention_no_item
are), so that domain's rows are not an EGRU comparison; they show the same
statistical-control-competitive pattern already visible in the main study.
